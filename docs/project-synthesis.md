## What Scout currently does

Scout uses a planner, bounded parallel scouts, an optional gap analysis with up to three deep dives, and one synthesizer. Deep dives are scout calls, not a fifth role. PydanticAI owns model and tool semantics; `scout.py` controls the run lifecycle; `evidence.py` owns evidence checks; Postgres stores runs and Logfire stores traces. The synthesizer receives a checked ledger as citable passages rather than raw tool transcripts. Model and limit defaults live in `config.py` and can be overridden through settings, CLI options, and study arms. [README](../README.md) is the command and workflow guide.

The current default route is Sol for planning, Luna for scouting, and Claude Opus 5.5 for synthesis. DuckDuckGo remains the default search engine; Serper, Brave, and Exa are available as configured alternatives. Fetching can fall back to open-access sources, Exa, and Firecrawl. These are *implemented choices*, not evidence that any paid alternative should become the default. The current code defaults allow up to two, four, or eight planned questions at quick, standard, and deep depth. Their ordinary soft envelopes are $2.14, $3.60, and $3.60; deep automatically uses its $5.85 follow-up envelope. A hard `--max-usd` cap applies only when supplied or required by a study/case command. [Configuration](configuration.md) gives the remaining limits and distinguishes code defaults from a run's saved effective settings.

The evidence chain now records each tool result's hash and receipt, retains full text for quote-bearing results, locates verified quote spans, and links summary, answer, caveat, and table-row assertions to their cited passage IDs. `research show RUN_ID --provenance` displays that chain. Contradicting passages are citable with a code-owned stance label. The support audit of a new report receives only the verified source text behind that assertion's displayed citation. A pointer and an occurrence check still do **not** establish that the passage entails the assertion; the separate semantic audit or human review must judge that. Older stored reports keep their historical source numbering and legacy audit behavior. See [evidence.py](../src/research_loop/evidence.py), [citations.py](../src/research_loop/citations.py), [audit.py](../src/research_loop/audit.py), and [the provenance lesson](lessons.md#provenance-of-new-scout-reports-29-september-2026).

## Unimplemented work, in priority order

These are proposed changes, not automatic work authorization. The approved [passage-evidence plan](passage-evidence-plan.md) carries out the evidence parts of items 1, 3, and 4, item 9, item 10, the passage unit that items 6 and 7 need, item 13, the funnel of item 14, and much of item 15. The findings above explain why each is still open. Favor a deterministic check or an offline evaluator over a new run role.

### 1. Make the report contract honest

1. **Structural and citation integrity:** require title, summary, and answer for `complete`; persist every mismatched native citation and its location in structured checks; give an ambiguous multi-sentence citation its own visible state. Test answer-only output, a swapped citation, a removed citation, a cross-section block, a table row, and an uncited factual summary sentence. Keep provenance integrity separate from semantic support.
2. **Atomic factual support:** split compound assertions for *evaluation* into checkable facts; judge each against the displayed passage or cited set, count unsupported additions, omitted requested facts, and irrelevant/redundant citations separately. Calibrate the judge on human-labeled examples before using it to select defaults. Code can validate pointers; it cannot prove entailment by string matching.
3. **Source identity and access:** separate fetched document/snapshot from scholarly work identity; stop treating an arbitrary DOI near a document's opening as its own; preserve meaningful URL case/query and versions; display a body window or PDF prefix as such. Attach extraction method, window/page offsets, and metadata origin to evidence shown to readers. Test reference-list DOI mentions and same-work/different-version cases.
4. **Coverage as sufficiency:** represent unaddressed, addressed-but-insufficient, supported, and conflicted requirements. For structured tasks, use subject × requested-field items. An empty claim or one with an unverified/irrelevant quote must not close a gap. Make a primary-source requirement testable rather than treating a model's `source_type` label as proof. For category research, trial a review/survey read requirement only if its effect on missing facts can be measured.

### 2. Improve the evidence funnel before broadening generation

5. **Scholarly relevance:** rank/filter OpenAlex/Crossref/arXiv results by query relevance before presenting citation-heavy off-topic papers; identify reviews and surveys; measure decisive-source recall and useful papers read, not only clicks. A simple lexical baseline precedes any learned ranker.
6. **Targeted acquisition:** add document-local search or page/section-aware chunks over acquired material, preserving tables, numbers, and stable locators. Test whether needed facts beyond the first PDF pages or broad 40,000-character windows become available. Consider in-flight fetch deduplication and remembered refusal hosts only with cancellation and source-policy tests. CORE is already integrated; it is not an open integration proposal.
7. **Measured follow-up and context selection:** distinguish missing, contradictory, inaccessible, and low-value gaps; record why a gap was left open. On fixed ledgers, test a deterministic passage selector with coverage and source-diversity constraints, preserving opposing passages. A smaller context must retain every manually marked decisive passage before it is judged by prose quality. Keep the one-wave follow-up until a second wave's yield is measured.
8. **Shared brief and allocation:** pass the original question and relevant scope/assumptions to each scout if an omission audit shows missing context. Instrument useful evidence per dollar/time before testing bounded redistribution of scout shares. Equal shares remain the baseline. Do not introduce a learned router.

### 3. Make lifecycle and money recoverable

9. **Checkpoint completed assignments:** store each checked scout result as it finishes, keyed by run/question/attempt; merge in plan order; recover a cancelled run without reissuing successful paid calls. Test a two-scout wave cancelled after one success, plus an ambiguous persistence failure after commit.
10. **Preserve inherited verification provenance:** a fixed-ledger child must carry its source evidence version and observation references, or explicitly revalidate against available original tool messages. Audit source records should resolve through the parent run. Missing observations should be labeled unknown, not silently promoted to v8 certainty.
11. **Price uncertainty and retries:** charge unresolved request reservations against the parent ceiling even when the run has a numeric known-charge lower bound; expose both amounts. Set ordinary synthesis HTTP retries explicitly. Capture model, search, and reading attempt costs and reconcile when possible. Test one failed write, one unknown billed attempt, an output-tier boundary, and two concurrent reservations.
12. **Deadline and rate-limit diagnostics:** test whether a 120-second return-within threshold starts a potential 600-second final scout request too late. Use `research breakdown` to separate model, tool, pacing, and retry time before changing limits. A cross-process token pacer is justified only by observed 429s from concurrent studies.

### 4. Establish a quality measurement that can decide

13. **One reader-visible projection:** version a report input shared where appropriate by rubric, quality, and support evaluators. Include summary, answer, tables, and caveats; do not award rubric credit for hidden inventory. Preserve judge v2 and quality v1 results unchanged. Validate quality verdict anchors and packet references in the new versions.
14. **Stage funnel:** on a small frozen set, record whether decisive sources were discovered, relevant passages acquired, facts captured as checked evidence, passages delivered to synthesis, and facts correctly rendered/cited. Mark missing telemetry unknown. Pair these with completion, known/uncertain spend, and latency so a final score can identify the lost stage.
15. **Independent test lane:** add hand-authored identity/quote/coverage fixtures and successful citation streams to the offline world. Exercise ambiguous citations, contradictions, fallback/refusal, incomplete sections, storage faults, and budget reconciliation. CI already has a PostgreSQL service; extend its integration tests for checkpointing rather than claiming there is no database CI.
16. **Case and judge discipline:** use a mixed set of short, structured, contested, and broad development questions. `drb2-task8` and `drb2-task68-plus` are tuned-on development cases; protect task82, task59, and task78 for confirmation. Report both rubric judges where decisions are close, human-review decisive disagreements, estimate the detectable difference before running, and keep failed/partial runs in every denominator.

### 5. Experiments and operational proposals still unproven

17. **Search/default decisions:** write up the Serper rerun and incomplete DeepSeek study under their frozen decision rules. A better empty-result rate is promising but does not itself select Serper. Compare candidate engines/models on several cases, then confirm any default change with repeated, paired runs and a hard cap. Re-evaluate deep depth and the v13 claim fix only with clean development/held-out design; the old roadmap's run queue is not current authorization.
18. **Broad-report methods:** trial STORM-style perspectives and a source-backed outline within the current planner/synthesizer boundaries; compare on held-out broad reports for missing dimensions, unsupported associations, reader organization, cost, and time. Trial bounded scholarly citation traversal only on literature tasks, measuring *new decisive passages actually read*. These are not reasons to add permanent persona or supervisor agents.
19. **Reproducible retrieval and prompt optimization:** use recorded search/page fixtures or an evaluation-only stable corpus for component tests; verify live-web transfer before adoption. BEIR-style relevance metrics diagnose retrieval, not report truth. A DSPy-style offline prompt optimization trial requires a calibrated metric and untouched confirmation set; freeze winners back into `prompts.py` rather than importing a runtime optimizer first.
20. **Small operational ideas:** cache warming for a shared prefix, study-cache prewarming, and speculative page prefetch remain unmeasured. Test only if breakdown shows material latency, and never pay for a page reader speculatively. Write a dated usage-policy inventory for each external API, including DuckDuckGo scraping, open-access endpoints, per-process pacing, and fetcher identification; revisit it before a new integration. Consider command-specific credential preflight and dependency-compatibility tests for `CitingAnthropicModel`. Keep DBOS, Temporal, Redis, a vector store, event sourcing, and a graph migration deferred unless a measured need appears.

A **top-down best-quality run** remains an idea from the old roadmap, not a current study spec. If revived, define its reader, case mix, baseline, comparison rule, estimated worst comparable cost, and hard ceiling before any paid run; then remove or cheapen one setting at a time. Do not infer a model or depth winner from one impressive report.

**Lower-priority audit cautions:** A PDF parser in `asyncio.to_thread` cannot be forcibly stopped; bounded processes and memory limits are a deployment question if arbitrary untrusted documents become common. Scout's public-address and redirect checks are real safeguards, while an environment proxy owns its final connection boundary; do not describe fetching as either universally safe or wholly unchecked. Exact replay also depends on acquisition and dependency versions and on whether stored transcripts were truncated. Validate frozen answer keys against original sources (the archived design singled out st05's Chinchilla context-length item); correct a bad key with a new rubric version, never by editing a graded case. These are tracked in the [27 September audit](architectural-audit-2026-09-27.md#9-lower-priority-observations-and-decisions-to-defer) and [archived study design](archive/scout-study-design.md#preparation-without-paid-calls).

## External framework lessons retained

The [framework review](research-frameworks-2026-09-29.md) and [architectural review](architectural-review-2026-09-29.md#lessons-from-other-research-projects-and-exact-integration-points) compare mechanisms, not Scout performance against other systems. Their published scores use different tasks, corpora, models, and evaluators.

| Reference | Transferable idea | Boundary for Scout |
|---|---|---|
| PaperQA2 and OpenScholar | Track decisive papers/passages through discovery, reranking, evidence, and answer; ablate passage selection and, later, scholarly citation traversal. | Start with a deterministic selector on fixed ledgers. Neither a large paper store nor feedback loops are justified before passage recall and semantic support are measured. |
| STORM | Perspective coverage and an evidence-backed outline can improve broad reports. | Test within existing planner/synthesizer roles; added breadth may also add unsupported associations. |
| ALCE, FActScore, and Ragas | Separate citation recall, citation precision, atomic-fact support, and context recall. | Calibrate against human labels and count omissions; an entailment score or high supported fraction alone can reward a terse incomplete report. |
| DeepResearch Bench II | Expert rubrics expose information recall, analysis, and presentation gaps. | Rubric presence is not source support; tuned-on task8 and task68-plus are development data. |
| DeepResearchGym and BEIR | Stable retrieval and explicit relevance labels make search/ranking experiments interpretable. | Use evaluation-only fixtures/corpora; confirm on the live web before a production decision. |
| Pydantic Evals and Logfire | Reusable typed evaluators and trace comparisons fit the existing Python workflow. | Postgres stays the durable run record; first reconcile evaluators on the exact report projection. |
| DSPy | Offline prompt optimization can search instruction variants after the metric is trustworthy. | Freeze a winner in `prompts.py` and test on untouched cases; no runtime optimizer is needed. |
| LangChain Open Deep Research, GPT Researcher, Anthropic Research, LangGraph | Shared briefs, bounded delegation, single synthesis, and recoverable stages are useful patterns. | Their topology is not evidence for a new Scout supervisor or graph runtime; try simple Postgres checkpoints first. |

## Suggested next sequence and gates

1. **Offline correctness pass:** close structural-completeness and citation-mismatch gaps, make coverage eligibility meaningful, and test document/work identity counterexamples. Acceptance: the new report never labels an uncited or ambiguous factual assertion as supported, an answer-only reply is partial, and an empty coverage tag does not close a requirement.
2. **Recoverability and accounting pass:** checkpoint per-scout output, preserve source evidence versions in reruns, and carry uncertain charges into the parent ceiling. Acceptance: a cancelled two-scout run retains its completed result without a second paid call; an unpriced attempt never releases study room.
3. **Measurement pass:** build the stage funnel and a versioned reader-visible evaluator; calibrate against human-marked decisive facts and omissions. Acceptance: evaluators agree on what report text was delivered, and disputed semantic verdicts are exposed instead of silently collapsed into `supported`.
4. **One-factor trials:** start with scholarly relevance/targeted acquisition on frozen plans and deterministic passage selection on fixed ledgers. Run dry and cheap checks as required by `AGENTS.md`, then seek the user's approval for each paid spec with a decision rule and hard ceiling. Adoption requires improvements on the targeted measure without a new decisive factual or source-attribution defect.
